## Evidence and implementation status

- **Mapped** means an inspected native mapping or extracted data structure identifies a resource/field. It does not prove every runtime rule or that the resource is used.
- **Documented** means an original manual or direct source describes behavior; version and remaining numeric-rule questions still matter.
- **Research** means the candidate needs original runtime observation, state/parameter tracing, or stronger evidence.
- **Prototype** describes our custom implemented adaptation; it does not claim original fidelity.
- **Proposed** describes an intended MMO use. Unless a row says otherwise, implementation and browser acceptance remain queued.

## Movement and model rules applying to every record

**First use the matching original Chao movement.** Only for a documented missing Chao capability, adapt the relevant original stage-character mechanic/motion. Create new movement only for a remaining documented gap. Native vehicle motion can animate a mech while the actual pilot keeps an appropriate native Chao motion. A filename match alone does not establish a usable action.

Never stretch the Chao rig to fit another character: preserve hierarchy, rest pose, weights, eye/wing/foot attachments and proportions. Use a uniform model-parent scale, deliberate retargeting for genuine gaps, normalized root motion, correct original timing and per-state loop/transition data. Animation cannot grant movement, items, hits or progression; the server owns permitted actions and results.

Every acceptance task below includes source provenance, version, original-vs-adapted rule labeling, save/reload where persistent, two-client visibility and rejection of forged client results. A visual mechanic additionally requires a live browser check of representative frames and transitions.
