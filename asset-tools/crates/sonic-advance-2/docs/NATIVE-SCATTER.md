# Single-player ring scatter

StageScatter runs the native recurring task at priority 0x2001: after the stage entity manager and immediately before the course objects that precede the player. It advances its own original ring animation (726, variant 0, twice normal speed) even if every slot is empty. A later enemy hit allocates slots and requests sound 118; its ring sprites first move and display on the next scatter task tick. The emitted rings share the stationary-ring tiles and the HUD's original OBJ palette bank 6; their script selects different native OAM frames. Collectible positions go to the same ring count, life and collection-effect code as stationary rings. Rendering should composite equal-priority slots in native OAM insertion order (earliest inserted in front).

Original emission is limited to the first 32 available slots. It takes the burst velocities from the cartridge sine table and updates the shared engine pseudorandom word once per allocated slot. A nonzero request plays the sound even if the slots are already full. The RNG is initialized to zero by game-engine startup, not by each stage restart. Other native consumers can advance it; exact whole-game sequences require the same preceding calls. A per-slot random bit prevents terrain probes for some rings, and the other rings test one tile on their assigned fourth-frame phase. Normal and inverted gravity use opposite bounce order, gravity acceleration and world-speed behavior. World speed, inversion and the optional second collision surface are explicit stage inputs.

The rings last 180 ticks regardless of camera visibility. Recollection first becomes possible on tick 33, checks the actual body animation rectangle without checking its hitbox index, and observes the original hurt/death guards. Camera edges are strict, final frames blink with stage time, and the displayed coordinate uses the pre-bounce position.

This does not model global OAM allocation failure, mosaic display registers, complete game RNG consumption or multiplayer.
