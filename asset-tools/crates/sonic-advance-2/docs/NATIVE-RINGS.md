# Stationary stage rings

The retail A2NE table at ROM offset `0x0D4BFC` contains 31 populated stage IDs and three null slots. Each populated entry points to a BIOS RL stream containing region dimensions, a sparse directory and terminated lists of ring coordinates. The Rust reader checks stream, directory and list bounds. Leaf Forest Act 1 starts at `0x098538`, expands to 4,434 bytes and contains 291 rings across a 78-by-12 regional grid.

The placement test compares the ordered positions of all 31 layouts with independent hashes from 24 original CSVs. Seven act-2 layouts have alternate level IDs. These results cover placement data only for the boss, unused and extra stages. To regenerate the metadata, run `python tests/reference_ring_layouts.py REFERENCE_ROOT REPORT.json` using SAT-R/sa2 commit `2dd3f17d30cd3c156e508aac0017620ae485b9ba`; the catalog records each CSV's Git blob ID.

In the normal single-player branch of `src/game/shared/stage/rings_manager.c`, the manager runs at priority 0x2000 before player movement at 0x3000. It searches regions using the player's sprite offsets and checks the player's rectangle against each ring's inclusive bounds extending 8 pixels on either side and 16 pixels above its origin. Each accepted placement is consumed once. The normal counter wraps as a u16; crossing a multiple-of-100 division boundary grants a life capped at 255 and requests 1UP music. Normal single-player initialization supplies three lives. Magnetic shields, dropped rings, boss respawns, extra-stage rules and multiplayer are separate paths.

The overlap test compares both upright and rolling player offsets across 7,938 positions to the pinned C macro compiled with Zig. Regenerate its digest with `python tests/reference_ring_overlap.py REFERENCE_ROOT ZIG_EXE .local/ring-overlap`. `cargo test --lib native_rings` runs the overlap, death, duplicate pickup and life-counter checks. With the verified cartridge in `A2NE_ROM`, run `cargo test --test source_native_rings -- --ignored` for placements and palette.

Standing rings use animation 726 with OAM order 20. The ordinary ring manager suppresses palette uploads. Both 726 and the pickup effect (727, order 15) contain a command for palette 161 at ROM offset `0x16C1E8`, targeting OBJ bank 6. In normal post-intro gameplay the HUD runs at 0x2102. Its ring animation 1127 refreshes bank 6 every frame from palette 163 at `0x16C228`; all eight HUD variants agree. The bank differs from 161 at index 13. See `src/game/sa2/stage/stage_ui.c:347` and `src/game/sa2/ui/stage_intro.c:702`.

The native pickup increments the counter before creating the effect. Below eight active effects, `src/game/shared/stage/collect_ring_effect.c` starts a panned ring sound, left for odd post-pickup counts and right for even. Animation 727 also emits sound command 117. The standalone renderer and mixer limitations are documented in the harness guide.
