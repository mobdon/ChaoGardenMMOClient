# Shared stage tasks in story levels

A story mount uses each verified SET's own object table. A placement reaches the ordinary ring or one of the two springs only when its native task address and original name match. The local index alone has no meaning across different stages. The ring also rejects the alternate terrain-following path. City Escape's board and music adapters remain stage-specific.

In the supported install, 844 ring placements, 42 spring A placements and 321 spring B placements select these partial callbacks. Six other placed City Escape objects retain their earlier partial callbacks, and 94 whistle pipes select their own callback, for 1,307 distinct placements total. The other native behaviors, scheduling, physical player movement and stage clear are open. Supplying an observed contact is not a simulation of that contact.

From the checkout, replay Green Forest layer 0, row 1 (spring B) or row 7 (ring). Use a fresh local output path and a local request using the spring or ring replay schema:

    sa2-assets fan-replay GAME/sonic2app.exe .local/spring.json PC_SA2 "Hero Story Sequence" 13 0 1 REQUEST.json

For a magnetic ring an active frame accepts magnet_players per shielded slot with position, collision_center and speed. When the native task calls CalcAdvanceAsPossible, supply the observed output position as advance_result. The trace distinguishes that external result from the selected player, travel distance argument, timer, spin decision and collision registration that Rust computes. A tie between two shielded players returns to ordinary ring behavior. The strict initial reach is under 50 native units; once the timer is positive the task can continue outside that distance. Neither the CLI nor these calls update a server wallet or a save.

The installed Green Forest test exercises both callback types, magnetic movement requests, ordinary pickup and destruction. The optional compare_magnet_c test compiles the complete o_ring_8 function from the pinned SA2B code used by the fixed-ring reference. The 200 scenarios vary eligibility, equal distances, both sides of the range boundary, a nonzero timer and timer wrap. The step argument is compared bit-for-bit on these host math fixtures. The external movement call is observed, not reconstructed.

The native whistle pipe uses PC function 0x6D95E0 and the SET name CHAOPIPE or chaopipe. The installed inventory finds 94 placements in 28 levels. Green Forest layer 0 row 194 is one. Supply `slot_zero_character` and a list of frames. A fresh in-range frame binds the callback. On following frames, `has_set_condition` models a non-null SET condition; `condition_flag_20` can mark an already-used pipe. When eligible, `nearby` supplies the native sphere query's selected slot and its task mode, for example `{"slot":0,"mode":42}`. Use null for no player. Radius is selected from slot zero's character even when slot one is returned. A whistle starts a 300-tick timer; entering an eligible update at 270 releases the object, sets the condition and flag, and plays sound 0x100A. Supply `transformed_point` only on that release frame: it is the observed result of transforming the pipe source point by translation then Z/X/Y rotation. The replay records the spawn request; it does not implement the spawned object's behavior, the spatial query, or an engine save.

Source: roeming/SA2B at 874a480379260dce01e8988d6ab13c0deddcee4c, src/OBJECT/o_chaopipe.c. The installed City Escape REL (section 1, 0x25528 init, 0x255D8 exec) confirms the control flow and separate single-precision multiply/subtract operations. From the worktree run `python asset-tools/crates/sa2/tests/stage_pipe_reference.py PATH_TO_SA2_ASSETS` with SA2B_REFERENCE, SA2_GAME_PATH, SA2_PC_CONFIG and CC configured (SA2B_ZIG_CC=1 for Zig). It compiles the pinned original executor with observed engine services and compares 160 ticks to the mounted Green Forest Rust output, including oscillator bits, timer, player action and ordered calls.
