# Big Foot opening

From the worktree, select Hero Story Sequence action 2 (level 60) using a private request and a fresh output path:

    sa2-assets --source-root GAME fan-big-foot GAME/sonic2app.exe .local/big-foot.json PC_SA2 "Hero Story Sequence" 2 REQUEST.json

For example, `{"work_allocation_ok":true,"frames":[{"player_position":[120,50,0]}]}` exercises the boundary at equality. Each frame supplies the current slot-zero player position. Only outside the boundary, add `vector_result` with the observed result of the imported helper. The callback passes the complete XYZ vector, writes 120 times the returned X and Z, and preserves the original Y. The first task invocation creates the boss; the frame list begins with subsequent stage updates. This is not a player controller.

The pinned boss_bigfootD.rel (module 81) registers its BIGFOOT descriptor in section 1 at 0x6434. The descriptor points to stage startup at 0x6460, teardown at 0x6628 and the stage task at 0x66BC. That task calls the boss constructor at offset zero with position (90, 0, 0) and yaw -0x4000, then installs the stage update at 0x67D4. This is the boss spawn, not an entry pose for Sonic. The successful boss work allocation is 0xC8 bytes; failure frees the boss task without preventing the stage callback switch. On success the boss installs eleven collision descriptors, starts in mode 1, and requests animation 6. The replay covers these decisions; the boss AI, model rendering, animation playback, collision resolution, damage, defeat and transition out of the fight remain open.

With SA2_GAME_PATH, SA2_PC_CONFIG and a Python environment with Unicorn PPC configured, run:

    python asset-tools/crates/sa2/tests/big_foot_ppc.py PATH_TO_SA2_ASSETS

The test executes the original stage task, constructor and state initialization, then the arena update including its local PowerPC square-root routine. It observes imported engine calls and the resource setup helpers. Both work-allocation paths and 202 updates are compared against Rust using the mounted story command. Those comparisons exercise equality, adjacent floats, unchanged heights, non-axis-aligned inputs and nontrivial vector-helper results; they are not an exhaustive floating-point proof. No executable bytes or generated output are checked in.

## Intro and player placement

The general single-player entry table has no Sonic row for Big Foot. The boss code supplies a separate, verified position: on its first mode-1 callback it writes (-boss.x, 0, 0) to slot zero. With the native boss spawn at (90, 0, 0), that places Sonic at (-90, 0, 0). This write establishes neither his yaw nor where the engine placed him before the callback.

Add `"intro":{"updates":451,"helper_task_created":true,"exit":{"query_result":1,"player_position":[-90,0,0]}}` to the request to run from fresh boss setup through the handoff to mode 2. For fewer updates omit exit. These count actual invocations of the mode-1 routine, independent of the stage arena updates; this is not a claim about elapsed wall time or global scheduler timing. The entry sets up the view, writes the player position, requests motion 6, calls the setup helpers, and sets the timer to 450. On the 450th subsequent invocation it changes the view, disposes of the optional helper, handles the native query, and enters mode 2 with timer and submode reset. A positive ordinary query result requires the current player position, since the native exit helper reads slot zero again; the first-frame position need not still hold. The local spawn call uses the adjusted Y coordinate and a zero-based argument capped at two.

The PPC comparison runs the mode-1 routine (section 1, 0xD90) and its local focus and exit helpers. Three complete trajectories compare player placement, camera argument blocks, ordered calls, flags, timers and transition state (1,353 boss updates). Imported calls and the effects of nested setup services remain observed. Combat AI after the handoff and victory are still open.
## Takeoff after the intro

The optional top-level `takeoff` array starts at the completed 451-callback intro handoff. Each item supplies the original outer engine's current boss `position`, `velocity_y`, and `motion_id`. Supply `motion_ready` only when the native routine actually queries animation completion. For example, `{"position":[90,0,0],"velocity_y":0,"motion_id":6}` is a valid first item. Stop at the transition to mode 3.

The Rust callback enables collision descriptor 8, requests motions 0 through 3, ramps the initial effect intensity, adjusts vertical speed and acceleration, and decides when the boss has settled at Y=10. The switch to the last takeoff submode requires both the height error and damped vertical speed to lie strictly between -0.05 and 0.05. It sets a timer of 30, but the handoff to mode 3 is gated by the animation query, not by counting down that timer here. The last submode also selects horizontal acceleration using the sign of the boss's X coordinate.

The PPC comparator executes section 1 at 0x1014..0x1628 with the native handoff state. It compares 192 updates across three trajectories, all five submodes, ordered motion/effect requests, flags, phase angles, and numeric motion fields. These are uninterrupted takeoff traces; the parent scheduler, impacts that interrupt the sequence, animation evaluation, generated effect instances, and world motion integration are outside this callback. Source descriptor offsets identify original effect data and are not replacements for the effects.


## Registering the boss collision shapes

The optional top-level `collision` array exercises section 1 callback 0x810 after successful boss setup. Each entry supplies `mode`, `flags`, `reference_y` (section 6 offset 136), the current boss `position` and XYZ `angles`, and three XYZ `anchors` (runtime vectors at section 6 offsets 180, 192 and 204). When flag bit zero is clear, also supply the three native `sine_results` in call order: X tilt, Z tilt, and Y displacement. An empty array reads the eleven authored descriptors without simulating an update. Raw header bytes, attributes, native parameters, angles, initial centers, section offsets and anchor bindings come from the verified local REL.

The callback calculates all eleven local centers from the three runtime vectors and the original per-shape offsets, including the extra displacement for mode 13 when the reference height is at most 13.5. It records the task pose seen by collision registration separately from the pose restored afterward. The host supplies anchor and sine values; this replay does not evaluate the rig, decide a hit, or apply damage.

The local PPC comparator runs 96 updates (1,056 center writes) across both sides of the mode-13 height threshold, equality, wrapped tilt angles, and both registration paths. It observes center submission and collision registration and substitutes vector addition and supplied sine returns for the imported math routines.
## Damage and lethal hits

The optional top-level `damage` array follows the branch immediately after the boss AI update. The replay starts with the actual health value loaded at section 1 offset 0x294 (4.0), carries health across callbacks and stops accepting callbacks after lethal damage. The host supplies the post-AI mode, submode, task byte 3, timer, flags, height and yaw each time. These are observations of intervening boss behavior, so this path by itself cannot play the fight.

Supply `child_hit` only when the child collision query runs, `body_hit` only when the fallback body query runs, and `player` (slot-zero flags and yaw) only for a positive body hit. Modes 10 and 13 bypass both queries. Flag bits 0x1000 and 4 suppress child-hit acceptance. Mode 9 can request the player impulse without losing more health. On a damaging hit supply `damage_work` containing the eleven current boss shape bytes at offset 3, the child shape byte, and the child's task and collision flags. Rust updates those fields, subtracts one health, and resets the boss submode, byte 3 and timer. A surviving boss selects mode 9 or 12 according to flag bit zero. At zero health, height below 5 selects mode 10, otherwise mode 13. The replay reports the impulse arguments and state changes; the collision searches, actual player motion, defeat sequence, score and story transition are separate.

The installed PPC comparator executes section 1 from 0x557C through the post-hit branch, including the two shape update helpers and the byte counter. It checks 291 callbacks across three traces, covering suppressed hits, body fallback, repeated hits, health carried from four to zero, randomized shape bytes and both lethal transitions, including height exactly 5. These tests observe the native search results; they do not manufacture a successful campaign result.

After a lethal hit, damage.defeatClock projects the boss timer from its next update. Below height 5, the first countdown takes 91 updates and the second takes 241; at or above 5, there is only the 241-update countdown. On the final update both paths wrap the timer to 65535 and call engine addresses 8001c78c and 80022bdc in order with argument zero. Nonlethal traces return null. The installed PPC comparator executes the timer and branch blocks, skipping intervening motion and effects. The engine calls are observations; their execution, story advancement and a playable clear remain unverified.

After a takeoff trace reaches mode 3, supply optional first_flight with ticks containing player_xz, boss_x and velocity_x. The first pass enables attribute 0x10 on collision shape 7, follows the player's X and clamps target Z to [-90,90]. Once the X gap is strictly below 10 it centers target Z; subsequent updates select the edge by horizontal velocity (zero chooses left). Crossing strictly beyond the selected edge at X +/-120 enters mode 4 and decrements the extra-work byte modulo 256.

The comparator executes module 81 section 1 from 0x163c to 0x19b0 from three completed native takeoffs. It compares both edges and helper dispatch as part of 306 first-pass updates. This covers the first pass with flag 0x200 clear. The position and incoming velocity are observations from the outer world update.

First-flight steering can now follow the takeoff phase counters through the unarmed pass. Supply optional first_flight.steering (angles and rates in pitch/yaw/roll order, previous_speed_squared) and motion on each tick (velocity_z, incoming acceleration, yaw_sin_cos, heading_difference and the optional turn_sine). Rust adds directional thrust and vertical acceleration, damps horizontal velocity, and carries yaw, bank, pitch and speed feedback into the next callback. The turn uses the engine sine result only for a doubled heading error strictly inside +/-16384; beyond that it saturates. Angles remain in original game units.

The installed PPC comparison runs the decision and steering paths through 0x1b14, including the local routine 0x3c8 and both turn-limit boundaries. External direction/angle and sine/cosine calls return observations. First-pass steering does not yet integrate the boss position or perform world contact. The helper and player effects beyond 0x1b14 are outside this calculation.

The original takeoff at 0x1468..0x1478 writes two and increments to three in the boss extra work. Rust carries that counter, flags and phase into the first pass. If the legacy extra_byte2 field is supplied, it must match takeoff. One completed pass leaves two.

Optional first_flight.turnaround runs only after crossing the first edge. Supply boss_xz and velocity_x each update, player_xz on entry only, and motion if steering is enabled. Mode 4 captures its target once, waits for inward velocity, then checks for |X| strictly below 150 on a subsequent update. It uses 0.09 horizontal thrust and 0.92 damping, including the exit update. With the first pass complete it sets flag 0x200 and reenters mode 3. The installed comparator runs the complete 0x1bcc callback after each of three native takeoffs and passes, with the two trailing helpers intercepted and their arguments checked. It checks both turn directions, zero velocity, exact boundaries, retained target and continuous steering. World motion and the effects of nested helpers remain separate.


For the full first flight cycle, append two entries to first_flight.repeat_passes, each with ticks and an optional turnaround in the same format as the first pass. The first turnaround enables flag 0x200. The next two passes keep the native steering state but use damping 0.94 and turn gain 0.07. Each creates and attaches a helper, controls it as the boss overtakes the player, and frees it at the edge. Supply helper_angles only on repeat updates while the helper is active. The original binding adds 4096 to roll with integer wrap and then limits it to [-3072, 6144]. The final turnaround consumes the zero counter and enters mode 5.

The installed comparator follows three complete three-pass sequences (537 pass/turnaround updates), without resetting the boss counter or steering between passes. It executes the native helper angle getter, enable routine, binding configuration and angle writer; task creation, attachment and deletion are intercepted. Player/boss movement and engine angle/trig results are observations. This establishes entry into mode 5, not its behavior, projectile hits, or a playable fight.


After both repeat passes and their turnarounds, optional first_flight.center_approach runs mode 5 submodes 0–2. Each update supplies boss_xz, velocity_x and motion in the existing steering format. Entry clears flag 0x400 and aims at the arena center. Inside horizontal radius 170 it clears collision shape 7 attribute 0x10 and switches flight coefficients for the next update. Inside radius 90 on that second approach, supply slot_zero_heading: the callback clears horizontal acceleration, stores the heading and current pitch minus 0x400, and advances to submode 3. Equality at either radius does not advance. Even starting at the origin requires two separate updates.

The comparator continues from all three original flight cycles into the installed mode 5 jump table, runs the native steering and distance helper, and compares 42 more updates, including diagonal boundary positions and immediate entry. Helper/engine calls for presentation and player heading are intercepted. The following aim phase continues from the stored pitch and heading; world motion and playable combat remain open.


Optional first_flight.aim continues from the inner center gate through mode 5 submodes 3–5. The replay records the corresponding arguments. It brakes each horizontal component independently, first seeks the stored pitch, then zero pitch, then requests motion 4. Its duration comes from the installed configuration at section 4 + 0x7c. With the original value 90, the half-duration check is strict: 45 stays in submode 4, 44 enters submode 5, and zero enters submode 6.

After the aim countdown, first_flight.landing accepts the observations for three successive states: align (incoming vertical velocity/acceleration, engine angle results in pitch/roll/yaw order, and heading_difference only at velocity >= -0.1), descend (height), and recover (motion_ready). On the first height <= 0 it levels pitch and roll, resets all three angular rates, sets the ground flag and height zero, and requests the original effects. The installed comparator continues from three complete aim traces through 78 landing updates. After landing and animation recovery, first_flight.ground_volley takes exactly eight launch observations (random_result, slot_zero_heading, heading_difference and player_position). The boss owns the timers, slot order and count; it captures the player position on each launch. Mode 8 releases the last occupied slot first, waits 15 updates between shots in a group, and uses a 45-update pause after each group of four. Once the second pause expires it requests motion 10, clears flag 0x100, then waits another 60 updates and enters mode 6.

The local comparator preserves all eight child handles across touchdown and executes both the boss callback (0x2820) and the original child launch routine (0x57d10). The engine random/angle implementations, interrupted combat and a playable clear remain unverified. Child flight can be replayed as described below.


After ground_volley, first_flight.recovery accepts the outer-engine observations consumed by mode 6. Use the string "update" on entry and for the final countdown; use {"heading": value} while the boss waits for the slot-zero heading to leave the inclusive interval [-16640,-16128]. During the turning animation, use {"animation":{"motion":7,"frame":14.5}}; omit frame for motions other than 7. The callback runs for 120 turning updates before reading the animation readiness query. Supply animation.ready on each such query, including false. On true, it requests motion 6 and waits 40 more updates before reentering mode 2. The two motion-7 event windows are [14,15) and [29,30).

Optional first_flight.next_takeoff requires that handoff. Supply velocity_x and acceleration_y from motion work at reentry, and ticks in the existing takeoff format. The second takeoff inherits the actual post-volley flags; the native callback resets its phase, intensity and burst on entry. Three continuous installed PPC comparisons include 513 recovery updates and 192 subsequent takeoff updates. They verify reaching airborne mode 3 with a renewed three-pass count after the full-health ground volley. Heading, animation, world movement and nested engine effects are still externally observed. This is one uninterrupted replay cycle, not a playable boss fight or story clear.


Each ground_volley launch optionally accepts flight with anchor_position (the child's last attached position) and ticks. An active tick supplies the engine's two atan_results, collision observations hit_player and hit_other, and rotated_vector only when the child calls the matrix transform (the first and sixth active updates). A paused tick makes no changes. The child retains the launch's speed, heading offset, angles and captured target. Rust integrates the six horizontal steps, constructs the four control points, samples the cubic and coasts on the last displacement. A zero-length or unrepresentable curve is reported as unsupported.

The replay records angle/rotation arguments, pose, velocity, curve time, and ordered impact dispatch. Ground height <= 0, horizontal radius > 160 and the two collision queries are independent triggers. The native callback can request multiple effects and frees in the same tick, then still register for collision. The replay ends at the removal request; it does not apply damage or render the effects.
