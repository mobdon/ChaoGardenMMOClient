# City Escape playability gap

The next dependency is a **build-matched reference for Sonic's controller and collision response**. The installed Steam game is a suitable reference target. A retail trace pairing input with resulting player state would let the Rust implementation measure its first divergence during the opening board descent. No equivalent trace or matching controller body was identified in the scoped audit on November 18, 2026.

The [City Escape board milestone](CITY-BOARD.md) now resolves the physical board, original motions and character parameters, and static terrain from both installed stage modules. We verified that the board **consumes** the rider state. Its result cannot stand in for the player update that **produces** this state. The opening geometric probe starts at (0,300,340) and hits the static road 513.4246521 units below. No per-tick trajectory or contact timing follows from these two points.

**Acceptance trace.** Record a single-player Mission 1 run on the pinned build from its original spawn through the opening board descent, transition to running, a ring pickup, checkpoint and goal/results screen. Include a checkpoint death/respawn branch. Record the initial stage and character state, input sampling cadence, per-tick buttons and axes, position, velocity, action, grounding/contact, camera transform, rings and mission timer. Retain an aligned video for visible transitions. Replay the same input from the same initial state through the Rust host. Compare the first divergent tick, exact discrete state transitions and reward counts, and report maximum position/velocity error per segment with a declared numeric tolerance. Each stage interaction must originate from the input-driven simulation. Capture a second run to establish the repeatability of the reference.
