# Wild Canyon stage entry

Run `fan-wild-canyon EXE OUTPUT.json PC_SA2_CONFIG_DIR "Hero Story Sequence" 5 true` with the source root set to the local install. Use false to observe failed background task allocation. Outputs and their source manifests belong in an ignored directory.

The PC story table selects character 4 and level 16. The mounted stg16D.rel is pinned by its land catalog hash. The module prolog at section 1 offset 0x8ab0 registers STG16; its descriptor identifies startup, teardown and the stage task. The first stage task (0x9140) requests Bg2Exec; on success it sets the field at 0x20 and the task-work position from the REL. Both paths install the empty successor at 0x91e0. The local PPC comparison executes the registration, both allocation routes and the successor.

The background position is not a player spawn. The startup resource replay follows the first 23 engine calls, from section 1 offset 0x8adc through 0x8c64. It verifies that the land pointer selects the separately catalogued level geometry and resolves the stage and background texture names, list pointers and object offsets in their original order. The PPC comparator intercepts the engine callees and checks the relocated arguments and tables in memory. The continuation checks the saved engine return at BSS offset 20, the floating-point arguments, the four slot/table selections and creation of CalcLightForPlayer. The return is symbolic in Rust; the comparator independently tries both zero and nonzero handles and checks the actual store and argument. Unknown engine functions retain their native addresses. Later startup, player lighting updates, engine resource loading, drawing and teardown remain unverified. Treasure placement, collection, Knuckles control, stage completion and the preceding Big Foot story clear are not verified by this command.

The mounted command also reads both complete installed lighting files and records their source hashes. The helper at 0xac90 derives the _gc.bin filename, converts twelve 32-byte big-endian rows into the first nine words of twelve 48-byte records, then copies the full GC file over that table. lighting.derivedWords preserves the nine intermediate words; activeWords preserves all twelve final words, including fields whose meaning remains unknown. This command requires both full files; partial and missing-file engine behavior is not reproduced. The installed PPC comparison runs the helper with file and string services supplied and compares intermediate and final words. It also checks the following volume call and both music requests: engine byte zero selects w_canyon.adx; nonzero selects t9_knuck.adx. Neither audio playback nor rendered lighting is exercised.
