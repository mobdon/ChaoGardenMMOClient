# Stage registration

Run stage-registration STAGE.rel OUTPUT.json with the normal --source-root restriction. The report identifies the pinned module, prolog, engine registration target, descriptor name and startup, teardown and entry callbacks. The descriptor offset is relative to section 5 and callback offsets to section 1. The output manifest retains the source hash.

The installed numbered modules share the same ten-instruction registration prolog. tests/stage_registration_ppc.py independently relocates each module and runs its prolog, capturing the descriptor passed to the engine. All 58 numbered modules match, including the shared stage 20 used by mech Tails in Hero action 7 and mech Eggman in Dark. Stage 42 has a verified registration identity even though it has no mapped terrain in the current catalog. Module count is not a count of unique story layouts or playable levels. This command does not execute any of the three registered callbacks.

stage20-entry stg20D.rel OUTPUT.json REQUEST.json replays the registered 1:0x1b90 callback. The request contains mode, position (XYZ), and targets (one nullable XYZ per update, observed through engine pointer 0x801e736c). Mode zero passes a packet referring to the task position to service 0x800c82dc, switches to one, then immediately performs the tracking update if the pointer is non-null. Other signed modes preserve the task state. The packet report includes only initialized fields, and positionAtCall is the pointed-to value at dispatch time. tests/stage20_ppc.py executes the installed entry for four successive updates at six initial modes. This does not execute the engine service, determine the target, or simulate the mech duel.

Optional startup input on stage20-entry takes character_queries (ordered signed engine returns for slot zero) and slot_one_present (observed after the selection call). A first result of 7 requests service 0x800b5858 for slot one. Otherwise the stage queries again and only a result of 6 requests 0x800b5ac4. A present slot one receives the mode-byte write and the recorded initialization calls; the replay ends before unconditional resource setup at 1:0x176c. Both engine calls and local helpers are reported, not executed by Rust. The PPC comparator runs twelve combinations including changing query results and independently observes the byte written to slot-one work.

When slot one exists, optional startup.walker observations expand the original local helper at 0x1584. Supply task_allocated and, only after success, work_allocated. After both succeed, supply character and slot_value (slot-one work byte 3 and float 0x48). The helper creates ControlTWalker, allocates 24 bytes, passes half the observed float to the next helper, and selects the native Tails or Eggman title texture list and cleanup callback. Failure of the second allocation dispatches task removal. The PPC comparator checks both failures, both characters and an unmatched character. Engine loading, subsequent controller updates, and the nested helper remain outside the replay.

Optional controller input replays dispatch at 1:0x754 and the state-zero opening block. Supply signed mode, engine_bytes ordered by offsets 0x39, 0x37, 0x42, and the two player_flags halfwords. If dispatch reaches the opening, supply opening.query, character, yaw and position from slot one. Engine gates leave mode unchanged; otherwise bit 0x4000 in either player's flags forces state 9. For state zero, query 16 writes state 1 and timer 360 and sends a character-specific resource request and a packet containing a position and adjusted yaw. The comparator checks every jump-table destination, both flag sources, gate branches, the ordinary no-transition case, and packet contents. continueAt marks the first block not replayed, including the shared update tail.

Optional tail replays 1:0x1424 through the common return using observations after its first local helper. The slot-zero flag, successive engine queries and engine word determine whether counters reset or advance. Reset sets the slot-one scalar to the native constant, may remove a child, and clears mode, submode and counter; ordinary progression increments the signed halfword with wrap and decrements only a positive cooldown. The stage then writes the scaled scalar and may request a new child. After a removal request, child_after_remove explicitly supplies the engine-owned link state. The comparator covers 24 combinations, including immediate recreation, signed wrap and both inactive cooldown cases. Nested helper effects and the game meaning of the scalar are unresolved.

State 9 dispatches straight to the common tail; state 10 shares the state 2 handler. Neither dispatch alone proves a duel outcome. Optional controller.state_seven expands the state 7 handler using slot_byte, counter, helper_result (only when slot_byte is 6) and draw (only on a transition). A nonzero helper return takes priority, entering state 6; otherwise a signed counter strictly greater than 120 enters state 2. Both transitions reset the counter and calculate the timer from REL constants and the supplied engine draw. With no transition the counter stays unchanged until the common tail. The comparator executes both original transition helpers across 36 cases. The initial decision helper, draw service and state 2/6 behavior remain separate.

For slot byte 6, state_seven.decision can now supply the original predicate inputs instead of helper_result (provide exactly one). work_word is null if the slot-one task has no work pointer at 0x40; otherwise it is the unsigned word at work+0x38c. A nonzero word succeeds immediately; otherwise the signed engine byte at 0x803ad494 decides by nonzero. The helper never reads either supplied player position. The comparator executes the helper and transition code together in 72 cases. The producers and gameplay meanings of the two engine fields remain unknown.

Optional controller.state_eight takes slot0/slot1 XYZ, the observed angle_return, pose_word from slot-one pose+6, slot_byte from player work+1, counter and conditional draw. The state supplies horizontal position differences to the angle service and writes the converted yaw and constant scalar. A zero pose word enters state 4 using the native timer helper. Otherwise a counter divisible by eight writes one to two engine bytes and clears the counter. These writes are at 0x803ad485 and 0x803ad495; neither is the state-seven predicate byte at 0x803ad494. The installed comparator checks all three branches and both timer formulas. The meaning of the flags and the engine angle and draw implementations remain open.

Optional controller.state_one takes signed counter and limit, submode, slot-one character and slot0_byte. While counter <= limit, only counter 120 sets cooldown 180 and requests the character-specific service for IDs 6 and 7. Expiry has priority if limit is already below 120. After expiry, submode zero consumes query and may request a stage effect with the native position and group; every expiry resets counter, enters state 7 and uses draw to compute its new timer. The comparator executes the state block with 37 observations including equality, both character requests, six effect groups and skipped calls. Engine services and the stage effect itself remain external.

On a state-one expiry that requests a group, optional messenger_allocated expands the stage-owned 0x26020 helper for the actual arguments (type 2, null parent). The original task label is ObjectMessenger. The replay captures the creation request, null return, and successful task/work writes around its nested initializer, including group, position, mode 6 and final service arguments. Twelve installed PPC runs execute the caller and helper together for all six selected groups and both allocation outcomes. The nested initializer, message contents, rendering and playback are not implemented here.

Stage 20 startup passes the module string mh0020 at section 5 offset 0x15bc4 to the message loader. message-bank MESSAGE.prs OUTPUT.json reads the offset table and preserves every payload byte, including original character encoding and inline controls. Group numbers are zero-based, matching the signed bounds check at 1:0x21b90. The output and its manifest are local; no message strings are checked in. tests/message_bank_local.ps1 compares all six groups in each of six localized files under both Message and MessageK to SA Tools 786 PRS.dll output (72 complete byte comparisons). These directories are tested independently; the reader does not choose one for a runtime or claim to render text or play voices.

Numbered message bank verification extends beyond stage 20: the local comparator checked 840 mh/eh archives in Message and MessageK, totaling 76,420 groups. Across 24 archives, 936 groups have a line feed after the NUL terminator. The reader retains that byte separately from the message payload. Its purpose at runtime is unverified; this check covers stored bytes and offsets, not display or playback.

Optional controller.state_two replays the shared steering block in modes 2 and 10 (1:0xad4 to 1:0xbd0). Supply slot0/slot1 XYZ, slot_byte, decision (observed return from 0x1b0), and angle_return. A nonzero decision writes the heading directly and selects the scalar by slot byte. A zero decision additionally requires turn.previous_yaw and turn.result: the stage passes the previous yaw, requested yaw and 0x180 to the turn service, then stores its return and a different scalar. Twelve local PPC comparisons cover both modes and both branches. The decision, angle and turn services are observed boundaries; later state logic and duel completion remain open.

The steering decision at 1:0x1b0 can also run from observed service inputs. Pass an object in state_two.decision with slot0_byte and distance_return. Slot zero byte 7 and a distance strictly below the native constant (100) select direct steering immediately. Otherwise supply facing.angle_return, previous_yaw and difference_return: the stage compares the signed difference result strictly against 0x3000. The angle used inside the decision is a separate call from the subsequent steering angle. The local PPC comparator executes helper and caller together, checking service arguments, return branch and resulting writes in 24 cases. Distance, angle and difference service implementations are outside this replay.

Optional state_two.after_steering continues both modes past 1:0xbd0. Supply pose_word (slot-one pose+6), scalar (player work+0x48), signed counter and limit. Slot byte 6 with a nonzero pose word and scalar below 5 enters state 8 immediately. Otherwise range.slot0_byte and range.distance_return drive the local distance helper: slot zero byte 7 extends its inclusive 70-unit test to strictly below 100. A match continues at helper 0x640. Outside range, the two slot-one bytes 6 and 7 can pulse two engine flags at different counter intervals and draw thresholds. Supply draw only on those intervals. If neither a pulse nor an earlier transition occurs, counter > limit reaches 0xd48; otherwise the common tail follows. The PPC comparison verifies 43 paths, including both range equalities, negative counters and competing pulse/expiry branches. The engine meaning of the flags and the downstream expiry decision are unresolved.

When the range helper matches, optional after_steering.close_range executes the state-five entry at 1:0x640. It always resets the state counter and enters mode 5. Supply the signed cooldown; a positive value skips all services. Otherwise services.queries supplies the two slot query returns in order. Exactly 1 triggers the associated slot call. services.slot_byte and variant are player-work bytes +1 and +4 observed after those calls. Bytes 6 and 7 select one of four requests; an unmatched byte skips the request. All nonpositive cooldown paths then write 480. The comparison covers 20 integrated entries and checks ordered engine calls and arguments. This is entry into mode 5, not execution of that mode on its next update.

Optional controller.state_five runs the close-range update through the shared tail boundary. The low two bits of player_word (slot-zero work+0x1c) gate a heading/scalar write; supply angle_return only when either bit is set. The stage samples range, then consults the existing walker decision only outside that range. An active decision transitions to mode 6 before the periodic draw. A successful periodic pulse resets the counter; otherwise a signed counter strictly above 64 enters mode 4. pulse_draw and timer_draw are independent service returns and required only on their respective branches. The comparator executes the installed state and its local helpers for 54 paths, comparing heading, scalar, mode, counter, timer and flag writes. Engine services remain external and these paths do not establish a duel outcome.

Optional controller.state_four runs mode 4 to the shared tail. Range takes priority and enters mode 5 through the same close_range helper used by modes 2/10. Outside range, slot byte 6 and a scalar below the stage constant enter mode 8; otherwise a signed counter strictly above limit enters mode 2 using draw. Remaining updates take steering observations: two phase_words independently read at engine +0x7c, two axis_returns, the two positions, angle_return and final_slot_byte observed after the angle service. The stage offsets slot zero in X/Z, computes the angle arguments relative to slot one, and writes the heading and character-dependent scalar. Thirty local PPC comparisons cover all four destinations, changed phase and player values between calls, timer equality and both timer formulas. The engine math and the shared tail remain separate.

Optional controller.state_six executes mode 6 through the shared tail boundary. Signed counter > limit enters mode 2 before scalar/range checks. Otherwise slot byte 6 may enter mode 8 on its low scalar or mode 2 on a range match. timer supplies the byte and draw sampled by the mode-2 entry helper. Continued steering takes the two original positions, final_vector after the engine vector/matrix calls, angle_return and final_slot_byte. Byte 6 selects a constant scalar; other bytes use wave.phase_word shifted left ten bits and the observed wave return. The 24-case local PPC comparison covers both transition timer formulas, entry priorities, angle inputs and both scalar writes. The vector transform and engine math are still observed boundaries; this is not autonomous opponent movement.

Optional after_steering.expiry executes the remainder of modes 2 and 10 from 1:0xd48. Its decision uses the same work-word/engine-byte predicate as state 7. Supply draws and slot_bytes in native consumption order (including the timer helper when entered); missing or unused observations are rejected. A true predicate enters mode 6 immediately. Otherwise a draw may select mode 4, then separate character checks and draws can select mode 7, falling back to the existing mode-5 close_range entry. All four reset the counter. The slot byte is read again after a failed character-6 draw; the comparator changes it during that call to test that distinction. Twenty integrated PPC observations verify expiry through the common tail boundary. Random number generation, engine services and the duel outcome remain unresolved.

Optional tail.slot1_position executes the arena-boundary decision at 1:0x0, called at 1:0x142c. The helper copies slot-one XYZ and compares each axis against the native origin plus upper and lower offsets. Equality is in bounds. If any axis is outside, it sends one corrected position for slot one to the engine and returns 1; otherwise it returns 0. The original pose is not directly modified. The local PPC comparator checks 125 combinations (below, on either face, inside, above for each axis), comparing the return and exact service arguments and checking that the input pose is unchanged. Applying the engine request and world collision remain outside this replay.

Optional startup.layout_handle continues startup from 1:0x176c through 1:0x17fc. Five preliminary service calls precede a request with both original layout filenames (set0020_s.bin, set0020_u.bin) and argument 1024. The stage stores the observed unsigned return in section-six BSS and forwards it unconditionally to the next service, even when zero. Numeric REL data-pointer arguments are section-five offsets; engine targets and filenames come from the installed module. The PPC comparator verifies the seven calls and handle propagation for zero and two distinct nonzero returns. This does not establish which layout the engine chooses, spawn the objects, or run the remaining startup calls at 1:0x1800 onward.

With layout_handle present, startup.background_allocated continues the startup trace through 1:0x18fc. The stage supplies floating-point constants and four indexed table references to engine services, requests stg20_light.bin via its local helper, then requests the BgExec task. Successful allocation installs three callback pointers; a null return skips all three writes. The installed PPC comparator executes from layout setup to 1:0x1900 for both outcomes. The trace records explicitly prepared arguments only. It does not execute the lighting helper, render a background or assign meanings to the unknown engine settings.

stage-light-base STAGE_light.bin OUTPUT.json converts the twelve base lighting rows without needing a GC override. Wild Canyon now shares this derivation. The stage 20 PPC loop at 1:0x7c18 was executed on all 52 installed base tables (51 numbered plus stgbl1), comparing all 5,616 written words and checking that the last three words per destination row were untouched by the loop. Output contains only the nine derived words per row. This check covers the base conversion, not override selection, engine upload or rendered lighting.

stage-light-table INPUT OUTPUT.json resolves the initialized words after the stage 20 lighting loader attempts its GC override. Give it the base filename to discover the adjacent _gc.bin, or the GC file itself for override-only assets. A full override replaces all twelve 48-byte rows. Without one, the loader clears only the first destination row before writing nine words per row; the last three words of rows 1–11 retain prior memory and are null in the report. The installed inventory has 14 pairs, four standalone overrides and 38 standalone base files. The comparator runs the native clear, derivation and conditional copy branches with controlled file-service results; it does not verify rendered pixels or short reads.

Optional background input to stage20-entry runs the BgExec update at 1:0x1c90 and helper 1:0x1e08 for the requested number of frames. records holds up to five initially active rows of six unsigned words each. The helper increments word 4 with wrap, then expires a row when the signed wrapped difference from word 5 exceeds the module-derived threshold. It compacts survivors in order. The two floating-point additions on surviving rows use the callback argument from the REL; other fields are preserved as raw words. The report includes activeCount and physical storage, including stale words beyond the active prefix. The comparator checks empty/full tables, threshold equality, expired records between survivors and wrap across successive frames. This does not yet identify the producer of the records or render them.

Optional background_draw input traces either BgExec callback installed at task byte offset 20 or 32. selected_position is the XYZ from the engine-selected position pointer. Both callbacks use its X and Z with a fixed REL Y; they then use different section-five data pointers. Offset 32 applies a second translation and calls local helper 1:0x1efc; offset 20 submits a section-five pointer to an engine service instead. Reports preserve the ordered calls and explicitly prepared arguments. This does not execute the nested helper, matrix stack or renderer.

With scene setup enabled, startup.callback_slots_occupied supplies four booleans in the order that the stage inspects engine table offsets 0, 8, 36 and 40. These are observations at the respective reads; a local call intervenes before the fourth. The final setup installs only missing callbacks, requests the named fog and message resources, writes a separate fourteen-word dispatch table (four targets then ten nulls), and submits the music and sound-bank requests. continueAt is null when the registered startup callback returns. This is a trace of stage-side operations: called helpers, file I/O, audio playback, engine state changes and subsequent mission execution are not implied.

stage-fog FOG.bin OUTPUT.json reads both installed fog file sizes. The 16-byte header has two signed halfwords, ARGB bytes and big-endian maximum/minimum distance words. The 528-byte variant adds 128 floating-point samples, stored with their big-endian halfwords in reversed order. Reports preserve float bits; tableBits is null for a header-only file. tests/stage_fog_local.ps1 compared all 38 installed files against SA Tools 786 FogData (19 of each size; 2,432 samples). Stage 20 requests stg20_fog.bin, which was absent from the installed gd_PC directory. The reader does not substitute another stage's fog or establish the runtime fallback/rendering result.
